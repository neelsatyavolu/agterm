# agl Core Harness Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A single Rust binary, `agl`, that runs a read/write/edit/bash coding agent loop against a local OpenAI-compatible model and saves sessions as JSONL.

**Architecture:** One crate, blocking I/O. `provider` streams chat completions over SSE; `toolcall` turns streamed output (native or text-embedded) into `ToolCall`s; `tools` executes them; `agent` runs the loop and enforces the context budget; `session` appends JSONL events; `main` is the CLI.

**Tech Stack:** Rust 1.95 (edition 2024), `ureq` 3 (HTTP), `serde`/`serde_json`, `toml`, `clap` 4 (derive), `tempfile` + `httpmock`-free tests (local `TcpListener` stub).

**Spec:** `docs/superpowers/specs/2026-11-08-agl-design.md`

## Global Constraints

- No dependency on tokio or any async runtime.
- No network calls other than to the configured/detected model endpoint.
- Release profile: `opt-level = 3`, `lto = "fat"`, `codegen-units = 1`, `strip = true`, `panic = "abort"`.
- Targets: release binary < 5 MB, `agl --version` < 20 ms cold, idle RSS < 15 MB.
- System prompt (without project context) < 600 tokens (measure as chars/4 < 600).
- Default tool output cap: 30 000 chars / 2 000 lines, whichever first; truncated output says how much was cut.
- Files under 400 lines; functions under 50.
- Code ported from Grok Build keeps its Apache-2.0 header; repo gets `THIRD-PARTY-NOTICES`.

## Review Focus

1. Model emits a tool call with malformed JSON arguments → the loop returns a tool error to the model ("arguments were not valid JSON: …") and continues, never panics. (Task 3 test `malformed_args_become_error_call`.)
2. Endpoint down or model unloaded mid-stream → one clear line (`agl: cannot reach http://127.0.0.1:11434 (connection refused)`), exit code 2, session file still valid JSONL. (Task 2 test `connection_refused_is_clean_error`.)
3. `bash` command that never exits or floods stdout → killed at timeout (default 120 s), output capped, process group cleaned up. (Task 4 test `bash_timeout_kills_process_group`.)
4. `edit` where `old` appears twice → refused with "appears 2 times; include more context", file unchanged. (Task 4 test `edit_ambiguous_match_refused`.)
5. Long session near the context window → old tool results elided, not the system prompt or latest user message. (Task 5 test `budget_elides_oldest_tool_results_first`.)

### Task 4: The four tools

**Files:**
- Create: `src/tools/mod.rs`, `src/tools/read.rs`, `src/tools/write.rs`, `src/tools/edit.rs`, `src/tools/bash.rs`, `src/tools/truncate.rs`
- Reference (port matching logic, keep header): `grok-build/crates/codegen/xai-grok-tools/src/implementations/grok_build_hashline/edit/apply.rs`, `.../util/file_reader.rs`

**Interfaces:**
- Consumes: `ToolCall`, `Config.bash_timeout_secs`.
- Produces:
  - `pub fn schemas() -> serde_json::Value` (OpenAI `tools` array; each description ≤ 2 sentences).
  - `pub fn run(call: &ToolCall, ctx: &ToolCtx) -> ToolResult`; `pub struct ToolCtx { pub cwd: PathBuf, pub bash_timeout: Duration }`; `pub struct ToolResult { pub ok: bool, pub output: String }`.
  - `read {path, offset?, limit?}`: numbered lines `{n:>6}\t{line}`, default limit 2000.
  - `write {path, content}`: creates parent dirs; returns `wrote N lines to PATH`.
  - `edit {path, old, new, replace_all?}`: exact match; else whitespace-normalized (trim line ends, tabs↔spaces) match; 0 matches → error listing the 3 lines most similar to `old`'s first line; >1 without `replace_all` → `appears N times; include more context`.
  - `bash {command, timeout_secs?}`: `sh -c` in its own process group, stdout+stderr merged, exit code appended; on timeout kill the group and say `timed out after Ns`.
  - `truncate::cap(s: &str, max_chars: usize, max_lines: usize) -> String` keeps head and tail, notes `[… N lines cut …]`.
  - Relative paths resolve against `ctx.cwd`.
